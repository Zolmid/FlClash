## Implemented domain changes and ownership

The following additions are adapted to existing owners rather than replacing main architecture:

- Core protocol: runtime rule list/stats/disable, manual DNS, bundled Core version, AGE tools and memory footprint are additive structured methods. `ChangeProxyParams.close-connections` is handled with chain-scoped application-wrapper connection closure. Main JSON envelopes, gomobile callbacks, event batching, desktop lease/lifecycle, request correlation and generation guards remain.
- iOS: CoreLib/Service uses native String envelopes, full SharedState, independent tunnel-state observation and AppGroup paths. Restore only acts on the latest run request/native state; route watch reconnects across app/extension Core ownership. Android byte/revision protocol is preserved.
- Mobile settings: NetworkExtension flags, Darwin recv/send message options, widget theme/quick label/panel and Android notification speed preferences flow through SharedState/native runtime snapshots. Requested and actual Android options remain distinct so fallback stacks do not create permanent restart prompts.
- Profile refresh: Application owns one ProfileAutoUpdater, ProfilesAction owns same-profile singleflight and shared latest-attempt timestamps. Latest manual success postpones auto refresh for the full interval; manual failure also bounds retries. Refresh entry points pass only a profile id, resolve the current provider source when idle, and join the latest queued Future when busy. Only the explicit source-edit API may enqueue a new URL/key snapshot; EditProfileView registers that intent before closing, so an old list/tray snapshot cannot queue source A after a pending edit B. URL/key edits serialize after active work rather than being lost. Startup missing-file recovery uses ProfilesAction.ensureProfileFile and waits for the latest queued source; SetupAction re-reads the profile instead of writing back an earlier snapshot. Resource updates still run at startup and periodically.
- WebDAV: configurable single-basename backup templates and normalized collections work with main staging restore and rollback. Collection/file/unknown are explicit; unconfirmed metadata never grants deletion. Authentication/redirect/collection targets are validated on every path, and DELETE never follows a different target.
- Updater: verified metadata/download/installer and SemVer are integrated through CommonAction, main Core lifecycle and SystemExitCoordinator. One CommonAction Future covers the entire download/verify/install sequence, including phase boundaries. Cancelled/failed package installation restores only the unchanged running intent after a confirmed stop. See [updater.md](updater.md).
- Main UI integration models: focused proxy navigation, runtime proxy metadata, chain collapse, hidden groups, TV override, foreground/idle polling settings, back-to-dashboard, editor line height, high-priority autolaunch and tray selection preferences. UI/native owners supply their final presentation/platform work.
- Core log source is explicit and filters compose with existing main text/keyword filtering. Already-root Unix launches use the direct existing launcher with no new privilege escalation. One failed geo-file initialization no longer aborts unrelated startup. Large desktop JSON frames decode off the UI isolate while ordered/generation-safe dispatch remains.

## Deliberate boundaries

`queryRule` with advanced metadata, accurate accumulated per-node traffic, overlay networking inspection/activation/ping/logout, system DNS mode, mapped geodata and serial low-memory loader require new mihomo fork APIs or implementation. Their candidate implementation was removed from production when the final scope prohibited submodule changes. The pre-scope Dart snapshot is preserved as `/workspace/patched-core-deferred/dart-before-scope-reduction.patch`; reference source SHAs below and [core.md](core.md) describe the prerequisites. No production API, model or entry point advertises these unavailable functions.

The existing upstream does not read endpoint-independent NAT. No new effective NAT setting/UI is added; the legacy raw iOS options field is ABI compatibility only and excluded from effective restart comparison. ICMP remains the existing per-profile override. Darwin sendMsgX stays false by default because main deliberately retained the kernel workaround; explicit enable still works.

Main database migrations, typed custom profiles, scoped managed-data cleanup, backup staging/rollback, BootGuard, macOS DNS restoration, instance lock, certificate/error handling, task pools, mobile/desktop lifecycle owners and package identity are preserved. These are concrete alternate implementations or safeguards, not reasons to discard a useful user-facing feature.
