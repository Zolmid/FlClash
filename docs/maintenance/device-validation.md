# 设备与系统网络验收执行单

本章提供可复用的 V3 执行步骤，不是一份已通过的设备报告。2026-11-15 的本次维护工作中，用户明确选择先完成不依赖真机的事务和文档，真机/VPN 验收单独保留。只读盘点中的物理 iPhone 当前不可达；模拟器记录不替代真机。

## 1. 先选择受验对象

同一版本号不能替代来源身份。每次验收先填好：

| 项目 | 必需记录 |
|---|---|
| 源码 | App SHA、工具 SHA、Core SHA、工作流 revision、锁文件/SDK版本 |
| 构建 | profile、渠道、构建模式、编译开关、平台/架构、版本和构建号 |
| 产物 | run/attempt、artifact ID、外层及最终文件摘要、内部provenance |
| 签名 | 是否有发行资格、签名身份/权限约束、描述文件/entitlements；秘密只留受限记录 |
| 设备 | 型号类别、OS/架构、当前安装版本、连接/授权状态、设备资源负责人 |
| 测试数据 | 隔离账号、测试订阅/配置、备份和允许触及的数据范围 |
| 网络窗口 | 可修改的设备、VPN/代理/DNS/路由范围、开始/截止、恢复负责人 |

已公开1.1.9的安装/签名记录证明的是 `bfb49ed8…`。main `d0af9d83…` 的CI开发产物证明的是相应编译/打包路径。不能把它们混成一个“新版本真机已通过”的结论。

iOS unsigned/ad-hoc 且无 provisioning 的开发IPA不能直接作为正式设备安装包。不得为绕过签名流程移动已有tag、伪造正式事件或覆盖1.1.9。需要新的可安装候选时，先按 [发布资格与来源合同](ci-release-and-recovery.md) 准备准确候选和授权。

## 2. 不触及真实数据的先行检查

先运行相应契约/故障夹具和静态平台检查。核对二进制架构、包名/Bundle ID、扩展、最低系统、版本、签名类型和需要的权限。确认脚本没有自动上传、签名、公证、启动服务或修改主机网络的可达路径。

在设备不可达、开发者模式/调试信任未建立、签名或安装资格缺失时，停止对应 V3 项。不要自动生成 ADB 身份、配对新设备、安装证书或改账号。保存准确阻塞，其他不依赖设备的检查继续。

## 3. 测试前的状态快照

1. 确认设备和测试账号均由本次窗口明确指定；不要使用不明归属的手机、VM或已登录用户配置。
2. 记录安装的包身份、版本、候选摘要和现有数据是否需要保留。
3. 保存允许触及的设置、代理、DNS、路由、VPN状态和自有进程/服务标识。公开报告只写脱敏摘要。
4. 为测试配置、备份和日志选择独占目录。代码回退不能自动恢复真实用户数据。
5. 先定义停止条件：无法确认进程退出、来源不符、身份不符、权限超范围、恢复失败或到截止时刻时停止新增动作。

SAFE_MODE 是主机启动的必要保护，但不是所有存储和账号自动隔离的保证。实际数据目录、Keychain/secure-storage、共享容器和服务仍须对照 [平台契约](platform-contracts.md) 核对。

## 4. 各平台执行矩阵

每个场景记录“输入/动作→观察→预期→结果→恢复”。只测试本次改动相关部分；没有执行的格子保留NOT_RUN。

| 平台 | 必需的原生场景 | 成功观察 | 不能用来替代的证据 |
|---|---|---|---|
| Android | 首次VPN授权/拒绝、通知权限拒绝、Quick Settings/Always-on/revoke、前后台、Doze、快速启停、网络切换 | ServiceState最新意图收敛，FGS/权限回调正确，无重复服务/陈旧running状态 | JVM单测、APK验签、ELF对齐 |
| iOS/iPadOS | 安装/覆盖升级、Runner/NECore/Widget身份与共享容器、VPN授权、锁屏/回前台、Wi-Fi/蜂窝切换、进程回收与续期 | TunnelCoordinator与真实NE状态一致，旧数据可读、续期不跨账号，系统安装与权限流程可完成 | unsigned编译、模拟器、CLI回读到应用存在 |
| macOS | 安装/升级、Gatekeeper、会话安全存储、窗口/托盘/深链、真实代理/DNS/TUN恢复 | App行为与Core进程状态对应，关闭后不残留本次网络改动或托盘实例 | DMG摘要、ad-hoc签名、本地widget测试 |
| Windows | x64与WOA分别识别、WinUI/Flutter宿主、Helper/SCM权限、启动/退出、网络与更新回退 | 服务拥有者明确，Core完整性检查生效，停止失败不会再开一个Core | Linux上cargo test、普通x64构建、另一种架构运行 |
| Linux | 实际图形会话、依赖/托盘、Helper/systemd/polkit、TUN、升级/退出替换 | 用户/特权边界正确，安装后功能和恢复完整 | 容器编译、无GUI的进程启动、包管理器安装成功 |

Windows full-OS 验收按既有项目选择使用 UTM；Docker 使用 OrbStack。不能把容器或Linux VM当作Windows/WOA证据，也不沿用已停用的Colima流程。

## 5. 功能与故障场景

### 会话、订阅和路由

- 新装登录、退出后再次登录、跨重启恢复、账号切换期间的迟到响应。
- 网络离线、DNS失败、超时、非2xx、无效JSON、签名/摘要/绑定不符、旧v1数据和未知字段。
- bundle到期、撤销、设备绑定变化、序号回退、存储不可用或损坏；失败不得回退为接受不可信配置。
- 节点/协议切换、自动组和回国路线启停、有效探测与过期结果；UI显示不能代替实际流量路径。
- WS断开后HTTP回退、重复/乱序消息、恢复后的去重和账号代际隔离。

协议和状态机先用隔离夹具验证，真实线路只在获准窗口中执行。不要将真实订阅或节点认证写入日志。

### 生命周期

- 启动中停止、连续重启、重复请求、权限拒绝、Core异常退出和迟到回调。
- UI关闭但后台仍运行、操作系统回收进程、通知/磁贴/托盘等非UI入口。
- 退出必须核对真实进程/原生服务。Helper无法确认Core退出时，应保留所有权并报告失败，不能以直接启动替代来制造双Core。

### 交易、更新与旧数据

- 礼品卡不确定结果后的恢复、同一幂等key重试、跨账号/面板隔离；只使用授权的测试数据。
- 支付返回、取消和超时不等于到账。真实扣款、退款和权益变更不是本次默认测试动作。
- 下载失败、摘要不符、磁盘不足、被中断更新、旧版本覆盖安装和回退入口。
- 旧数据库/偏好/备份先在隔离副本验证。未知字段、规则顺序和跨版本拒绝规则保持语义；迁移中断后再次启动必须可解释。

## 6. 失败分类与停止

| 结果 | 含义 | 下一步 |
|---|---|---|
| PASS | 指定设备、源码和场景实际符合预期 | 保留输入、日志和恢复结果 |
| FAIL_NEW | 新候选引入可复现回归 | 保留最小复现，修复后重审受影响范围 |
| FAIL_BASELINE | 相同输入在原基线也失败 | 单独记录，不把旧缺陷当新改动通过 |
| BLOCKED_ENV | 设备、权限、签名、OS或工具条件不足 | 精确列缺口；不改版本/门槛掩盖 |
| NOT_RUN | 该项未执行 | 不进入通过统计 |
| NOT_APPLICABLE | 对本次改动确实不适用 | 写明理由和适用范围 |

出现未授权的数据/网络/签名副作用时停止受影响项。无法确认自己启动的进程已经停止时保留其占用，不重派同一资源；不能按名字kill用户自己的App或全局服务。

## 7. 收尾与恢复

1. 结束本次启动并已记录身份的执行实例，不操作无法确认归属的进程。
2. 核对设备上的VPN、代理、DNS、路由、服务和测试数据；只恢复本次拥有的改动。
3. 不覆盖已发布同版本内容。对新产生的数据明确能否降级；不能用Git revert代表数据已恢复。
4. 记录恢复失败或状态UNKNOWN，明确下一负责人和最小动作，不把未完成恢复标为完成。
5. 将结论绑定准确源码、设备类别、OS、构建参数、包摘要和测试场景，再决定是否允许下一层发布资格审查。

当前选择是先完成所有非真机事务和文档。设备连接、隔离账号/数据、允许的网络窗口及可安装候选准备好后，按本执行单建立独立验收任务，不直接重用旧窗口的批准。
